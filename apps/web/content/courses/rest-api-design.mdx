## What you will learn

Good API design is a multiplier. A well-designed API enables every client to move independently, scales without breaking changes, and communicates intent through its structure alone.

### REST fundamentals
- The REST constraints: stateless, uniform interface, layered system
- Resources, representations, and URLs that make sense
- HTTP semantics: methods, status codes, headers done right
- HATEOAS: navigable APIs vs. documentation-only APIs

### API design in practice
- Naming resources: nouns not verbs, plural not singular
- Pagination: cursor vs. offset, pitfalls of large offsets
- Filtering, sorting, and partial responses
- Error response design: consistent, informative, not leaky

*Informed by real enterprise integration work with IBM WebSphere DataPower, MuleSoft Anypoint, and building integration platforms across financial services and telecoms.*

### GraphQL
- The query model: ask exactly for what you need
- Schema design: types, queries, mutations, subscriptions
- DataLoader and the N+1 problem
- When GraphQL is the wrong choice

### API security
- Authentication vs. authorisation
- OAuth 2.0 and OpenID Connect: flows and when to use each
- API keys, JWTs, and mutual TLS
- Rate limiting and throttling strategies

### Production concerns
- OpenAPI / Swagger: design-first approach
- Versioning strategies: URL, header, content negotiation
- Breaking vs. non-breaking changes
- API gateways and their role (Kong, AWS API Gateway, MuleSoft)

### AI-powered APIs
- Designing APIs that wrap LLM calls
- Streaming responses with Server-Sent Events
- Tool schemas for agent function calling
- Building MCP servers as structured APIs

## Course outline

1. REST constraints and why they matter
2. URL design and resource modelling

5. API security: OAuth 2.0 and JWT

8. Versioning, breaking changes, and deprecation
9. APIs in the AI era: streaming, tool schemas, MCP
